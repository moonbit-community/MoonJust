## Scope statement

Phase 1 established the target-independent source, diagnostic, path, host, and
application boundary required by the lexer and all later runtime work. It did
not implement justfile lexing, parsing, formatting, loading, or recipe
execution. At that historical point, MoonJust remained an alpha foundation and
was not yet a replacement for `just`.

The 2026-08-06 re-certification verifies all five contract rows with the
structured manifest validator and exact Native/wasm outline counts. Public
interfaces remain generated by `moon info`; the Phase 3-5 remediation does not
invalidate these Phase 1 contracts.

Coverage note: the all-package run is evidence of execution, not a claim that
the later core-package 90% release threshold has already been met.

## Frozen decisions

- Source identity and all source spans are based on validated UTF-8 bytes.
- Human positions are one-based lines with separately reported zero-based byte
  and Unicode scalar columns. Display-width policy remains a renderer concern.
- Diagnostic IR is structured and cannot contain ANSI ESC. Text rendering is a
  replaceable presentation layer.
- `PathValue` always carries an explicit Unix or Windows flavor and performs
  lexical operations without reading the current host OS.
- Core host effects cross the project-owned `HostFs`, `HostEnv`, `HostProcess`,
  `HostClock`, `HostRandom`, `HostTerminal`, `HostSignal`, and `HostPlatform`
  interfaces.
- Capability denial and capability unavailability are distinct errors.
- Process requests remain structured as program, arguments, cwd, environment,
  and stdin; shell command concatenation is not a Host API.
- CLI usage errors exit 2, ordinary application errors exit 1, recipe statuses
  are propagated, and signal statuses map to `128 + signal`, following the
  pinned upstream source.
- Public API evolution follows ADR-0006 and generated-interface review.

## Known limitations and assigned gates

- The diagnostic renderer uses Unicode scalar columns, not terminal display
  width. PR-062 and the Unicode-width dependency gate own aligned terminal
  output.
- `PathValue` is lexical. Filesystem canonicalization, symlink identity,
  permissions, and case behavior belong to real HostFs adapters and loader
  phases.
- FakeHost proves contracts and deterministic error paths; it is not a Native
  or wasm1 filesystem/process adapter. PR-070, PR-080, and PR-087 own those
  implementations.
- `ApplicationRequest` is a composition value, not an argv parser. PR-060 owns
  full CLI parsing and exact help/error output.
- No Phase 1 package lexes or executes justfiles. At the Phase 1 snapshot, the
  command continued to reject those claims explicitly.

No limitation above blocks Phase 2. Each is attached to the later compatibility
gate that can resolve it without weakening the Phase 1 contracts.

## Phase 2 entry

Begin PR-020 only after the Phase 1 pull request and required checks are green.
The lexer must consume `Source` bytes, emit byte `Span` values, produce
structured diagnostics, and run its shared corpus on Native and wasm1. It must
not read files, environment variables, platform globals, or process state.
